# Current Status

This file is the short source of truth after ADR-11. When it conflicts with historical PRDs or Phase 0 spikes, the order of authority is: code, status JSON files, ADR-11, then this file. Historical docs remain useful for intent and rationale, not for shipped scope.

## Shipped

- Runtime: Rust workspace with a headless `agent-core`, Ratatui TUI, headless `-p` mode, JSONL sessions, resume, and `/goal`.
- Provider: one wired adapter, `OpenAiChatGpt`, using the ChatGPT subscription channel through the Codex backend. Responses WebSocket is preferred, bounded to one response in flight and one turn-scoped continuation state, with deterministic HTTP/SSE fallback. The opt-in live probe passed on 2026-08-01 with upgrade 101, initial metadata, `generate=false` prewarm, accepted `previous_response_id` reuse and a terminal real response. Delivered by EP-003 of `tasks/prd-parite-client-modele-codex-api.md`.
- Auth: OAuth PKCE flow and refresh-token rotation for the ChatGPT subscription, stored in the OS keyring.
- Frontier runtime contracts: each selectable model resolves to one validated `ResolvedModelRuntime`; each sampling captures one fingerprinted `PromptSnapshot` and one generation-bound `StepToolPlan`; `end_turn=false` continues without synthetic user input; tool outcomes use one typed, bounded `ModelToolResult`; thread admission, terminals and cold-recovery repairs are commit-coupled. Provider reopenings share one `max_attempts` budget that includes the initial request, refresh, reasoning-replay downgrade and overload fallback. `retry_scheduled` exposes turn, step, ordinal, exact class, delay and fingerprints without error bodies; a 401 permits one cancellation-guarded refresh per sampling, then requires reconnection. Still deferred: public server-owned Responses mode, live validation of encrypted reasoning replay, and provider adapters beyond `OpenAiChatGpt`. Delivered by `tasks/prd-frontier-harness-runtime.md`.
- Code Mode: a durable JavaScript session per thread, on V8 (`v8 = "=149.2.0"`, the Codex baseline pin). One isolate and one OS thread per CELL, which the US-005 spike measured at 4.1 ms P95 for a cold session and 3.2 ms P95 for a warm cell: that price buys concurrent cells, a CPU/heap/native quota per cell, and a cell that wrecks its isolate taking nothing else down. Cross-cell state is explicit (`store`/`load`, scoped to the thread's session), never the global object, and two threads share nothing. A cell is bounded three ways and the three are told apart: 30 s of CPU stopped by an external handle, 256 MiB of V8 heap, 256 MiB of native memory. V8 routes a refused array-buffer allocation through the near-heap-limit callback too, so the allocator flag is what distinguishes a native breach from a heap one. Globals are an allowlist: `text`, `image`, `audio`, `store`, `load`, `notify`, `yield_control`, `exit`, `tools`, `ALL_TOOLS`, minus `console`, `Atomics`, `SharedArrayBuffer` and `WebAssembly`; no file system, no network, no module loader. The model surface is the Codex pair, `exec` (freeform, baseline Lark grammar, first-line `// @exec:` pragma refused rather than ignored when malformed) and `wait` (strict function). `exec` has NO effect of its own: every `tools.<name>(args)` call goes back through the SAME `ToolDispatchSnapshot` the step captured, hence the same permissions, taint, hooks, approval memory and cancellation a direct call meets, which is why the pair is `Allow` and not `Ask`. A `code_mode_only` model sees only `exec` and `wait` while the nested tools stay dispatchable and hidden; a `code_mode` model keeps its direct tools as well; a direct model never sees the pair. The session follows the thread: opening, forking, rewinding or resuming a thread closes the previous session and opens an empty one, so a resumed thread never replays a cell and a crash leaves its `exec` call to the ordinary orphan-call reconciliation. Without a V8 runtime nothing changes for a direct model: the pair is not registered, the catalog keeps refusing a code-mode model before any request, and the refusal names the missing component. Delivered by EP-002 of `tasks/prd-parite-totale-codex-cli.md`; `crates/agent-code-mode/`, `crates/agent-code-mode-v8/`, `crates/agent-tools/src/code_mode.rs`, measurements in `tasks/spike-verdicts.md`.
- Multi-agent v2: the six tools a frontier model orchestrates with (`spawn_agent`, `send_message`, `followup_task`, `list_agents`, `wait_agent`, `interrupt_agent`) are registered in the binary and point at a real `AgentSupervisor` and a real spawner. Which models SEE them is decided per step from the catalog's `multi_agent_version`: only `v2` gets them, `v1` and `disabled` get exactly the plan they had before, and none of the six adds a line to a system prompt. A child is addressed by a CANONICAL NAME (`spawn_agent(task_name: "reader")`, then `followup_task(target: "reader")`) resolved from the caller's own position, so a relative name never escapes its subtree and a reused one is refused before a slot or a creation is burned. A child IS a thread: its own durable log next to its parent's, its own turn lifecycle, and a tool registry BUILT from its granted authority (the authority intersection decides tool by tool, so a read-only child has no mutating tool to be refused at), with no human approver and no multi-agent tool of its own, which is what makes the depth limit structural. `send_message` queues durably without opening a turn and `followup_task` opens one on an idle child or joins the running turn of a busy one, never a second concurrent turn. A restart rebuilds the graph, the names and the undelivered mail: what was RUNNING is closed with the restart as its cause, what was IDLE stays addressable and its next follow-up reopens its own log, and a log that cannot be reopened makes THAT child `failed` with a visible cause while its siblings stay drivable. A parent shutdown persists a terminal cause for every active descendant, timeout included. A `code_mode_only` model hides the six from its surface and still dispatches them from a cell through the same `ToolDispatchSnapshot`, so the two paths return the same content, the same state and the same normalized error. Delivered by EP-003 of `tasks/prd-parite-totale-codex-cli.md`; `crates/agent-runtime/src/{agent,supervisor,path}.rs`, `crates/agent-tools/src/agent.rs`, `crates/agent-cli/src/subagents.rs`, acceptance in `crates/agent-runtime/tests/multi_agent_v2.rs` and `crates/agent-tools/tests/multi_agent_dispatch.rs`.

- App-server: `pyxis --app-server` serves the external client contract as JSON-RPC 2.0 on standard input/output, and `--listen 127.0.0.1:<port>` serves the SAME contract over WebSocket. Eight methods under the Codex baseline names (`initialize`, `thread/start`, `thread/resume`, `thread/unsubscribe`, `thread/items/list`, `turn/start`, `turn/steer`, `turn/interrupt`), eleven notifications and four server-to-client requests. `initialize` precedes every mutation, negotiates the version and publishes what this build can do before a thread exists; a broken message, an unknown method and an incompatible version each get their own JSON-RPC code and the connection serves the next request. ONE thread is open per process, because the tool registry, the Code Mode session and the sub-agent handle each belong to the open thread: a second client gets `-32002` naming the thread that is held, arbitrated across both transports. An item is named `item_<n>` after its rank in the DURABLE projection, so a live identifier is the one the same item carries once re-read from disk; a message abandoned before commit gives its number back, and an engine error report is named in the `error_<n>` namespace instead of consuming one. An approval crosses into the unchanged permission pipeline and carries `threadId`, `turnId`, `itemId` and `callId`: the event pump polls the runtime BEFORE its own command queue, so the item a call opens is always projected before the approval that call raises, and the correlation is deterministic rather than lucky. Everything is fail-closed: no client attached, a silent client, an unreadable answer or a cancelled request all deny; a late, duplicated or terminated-turn answer is refused and reported without reopening an item. A client declares its own tools at `thread/start` and they enter the same registry as the built-in ones (confirmation by default, sensitive, untrusted output, never remembered), executed back on the client through `item/tool/call`. An interruption closes every open item exactly once and releases every pending request. `thread/items/list` pages the durable log by an opaque, thread-bound cursor; a connection holds at most 1 024 messages or 16 MiB in flight, past which it is closed with a named cause and nothing committed is lost. JSON Schema and TypeScript are derived from the Rust types (`schemars`) and published in `docs/app-server/`, byte-compared by a test. Divergences and the reasoning behind them: `docs/app-server/README.md`. Delivered by EP-005 of `tasks/prd-parite-totale-codex-cli.md`; `crates/agent-app-server/`, `crates/agent-cli/src/app_server.rs`, acceptance in `crates/agent-app-server/tests/protocol.rs`.
- Tools: `read`, `glob`, `grep`, `write`, `edit`, and `bash`, with fail-closed tool metadata, permissions, taint propagation, and concurrent read dispatch. EP-003 of `tasks/prd-parite-codex-par-le-code.md` adds five more, all through the same pipeline: `update_plan` (Codex item shape, at most one step `in_progress`, published as `AgentEvent::Plan` and rendered as a single transcript block that an update replaces instead of stacking), `apply_patch` (the apply_patch format the `*-codex` models are trained on, all-or-nothing: parsing, path guardrails and text application happen in memory, so a stale context writes nothing), `view_image` (media type decided by the file's magic bytes, refused outright when the provider declares no vision, the image entering the transcript as a user-side image block that full compaction already strips), and the `exec_command` / `write_stdin` pair (a persistent shell session whose standard input stays open, closed after 300s of inactivity or when the run ends, with its process tree killed).
- Sandbox: a policy with data-carrying variants (`agent_core::sandbox::SandboxPolicy`), selected by `sandbox_mode` of `~/.pyxis/settings.toml` (a security key, so never from a workspace file) and applied by Linux Landlock for the process tree, plus a cooperative local HTTP(S) proxy for subprocesses that honor `HTTP(S)_PROXY`. `workspace-write` (default) grants the workspace, the temporary directory, and any extra root declared in `writable_roots`; a root pointing at `/` or at the whole home is refused. `read-only` grants nothing but the session directory Pyxis needs to record itself, as a ruleset of its own rather than the previous one minus the workspace, since Landlock rules only add. `full-access` builds no ruleset at all, and `--no-sandbox` is its alias. Network access is carried by the policy: a closed policy ignores any `--allow` list and says so, and an authorization covers the subdomains of the host it names on a label boundary (`github.com` covers `api.github.com`, never `evil-github.com`, and `api.github.com` does not cover `github.com`). A degradation never keeps the requested name: the status line and stderr name the policy really in force. Delivered by EP-001 of `tasks/prd-parite-codex-par-le-code.md`.
- MCP: config loading, lifecycle state, tool listing, and tools callable by the model, over **two transports**. stdio spawns a subprocess; a `"type": "http"` entry talks Streamable HTTP to a remote server through an implementation of `rmcp`'s `StreamableHttpClient` written on the workspace reqwest client (the SDK's own variant pins reqwest 0.13 and would duplicate the HTTP/TLS stack). A remote URL must be `https`, or `http` on a loopback host, otherwise it is refused before any connection; the bearer token is declared by the NAME of an environment variable, read at connect time, so nothing readable enters the config, the logs or the transcript. The connection is bounded (10 s, and 2 s at startup) and a server that fails never blocks the session. Their tools enter the registry as `mcp__<server>__<tool>` with deterministic shortening under the 64-byte API limit and schemas rewritten into strict mode, every result is untrusted, and a server declared by the workspace still requires `/mcp <server> trust`. Per server, `enabledTools` then `disabledTools` (that order, from Codex) shrink the exposed surface without disconnecting the server, and `toolsApproval` sets an approval level per server that a per-tool entry overrides; a workspace-controlled file may restrict but never auto-approve, and no approval setting survives recent untrusted taint in the turn. A server connected or disconnected in session changes what the model can call **from the next turn on**: the change is staged and applied at the turn boundary, so a turn in flight never sees its tool set move. Delivered by EP-003 of `tasks/prd-harness-capabilities.md`, then EP-004 of `tasks/prd-parite-codex-par-le-code.md`.
- Skills: `SKILL.md` files read per the open Agent Skills spec (restricted frontmatter reader, no YAML dependency: the `name` and `description` scalars, plus the `allow-implicit-invocation` policy). Two scopes (US-018 of `tasks/prd-parite-codex-par-le-code.md`): `~/.agents/skills/<name>/` for the user and `<workspace>/.agents/skills/<name>/` for the project, the project version masking the user one at equal name with a trace. The root of each scope is fixed in code, so a repository supplies skill CONTENT and never the location it is read from. A skill declares no capability whatever its scope: `permission_mode`, `writable_roots`, `allowed-tools` and the like are ignored like any unknown key, and what a project skill produces is injected text framed as untrusted, exactly like its `AGENTS.md`. Names, scopes and descriptions are injected per turn as user-level context under an explicit byte budget; a skill whose policy forbids the implicit invocation stays out of that catalog and remains invocable by `/<name>`, which injects the body for the turn, ephemeral like the project context, with the invocation readable in the persisted transcript. Angle brackets and control characters of the frontmatter are neutralized, a symlinked `SKILL.md` is refused, and an invalid skill is dropped with a trace. Deferred: the `scripts/`, `references/` and `assets/` directories of the spec. Delivered by EP-004 of `tasks/prd-harness-capabilities.md`, then EP-005 of `tasks/prd-parite-codex-par-le-code.md`.
- Hooks: `[[hooks]]` entries of `~/.pyxis/settings.toml` (global only) declare commands run around each tool call, on the Claude Code contract: JSON event on stdin (`hook_event_name`, `tool_name`, `tool_input`, `cwd`, plus a bounded `tool_response` for `PostToolUse`), JSON decision on stdout under `hookSpecificOutput.permissionDecision`, exit code 2 blocking with stderr carried to the model. Two deliberate deviations, both fail-closed: a hook can only tighten (`allow` reads as "no objection", never as a bypass of a confirmation or of the taint defense), and every failure denies (missing executable, 5-second timeout, non-zero exit, unreadable stdout, unknown decision). A `deny` outranks `BypassPermissions`; an `ask` forces a confirmation in every mode and is never rememberable. A hook is executed directly (no shell) and inherits the Landlock confinement of the process, so it cannot write outside the writable roots of the session. Without a declaration nothing is spawned, cloned, or delayed. Six of the eleven reference events are supported (US-017 of `tasks/prd-parite-codex-par-le-code.md`): `PreToolUse` and `PostToolUse` around a tool call, plus `SessionStart`, `UserPromptSubmit`, `Stop` and `SessionEnd` around the session, each carrying `hook_event_name`, `cwd`, the `session_id` and its own field (`source`, `prompt`, `reason`). A lifecycle event names no tool, so a `matcher` declared on one is dropped with a warning. `SessionStart` and `UserPromptSubmit` still gate something and are fail-closed: a refusal, a failure, a timeout or an `ask` (which has no confirmation to request there) stops the session or the turn, naming the event and the hook. `Stop` and `SessionEnd` fire once the thing they observe is over, so like `PostToolUse` they decide nothing and their own failure is reported to the human; a blocking `Stop` would force the model to keep going, which is a hook WIDENING the run and not tightening it. The five remaining reference events have no anchor point in Pyxis. Delivered by EP-005 of `tasks/prd-harness-capabilities.md`, then EP-005 of `tasks/prd-parite-codex-par-le-code.md`; `crates/agent-tools/src/hooks.rs`.
- Observability: a panic restores the terminal before printing anything, then appends a dated report (version, location, message) to `~/.pyxis/logs/panic.log` and names that path on stderr. `PYXIS_LOG=error|warn|info|debug|trace` installs a `tracing` subscriber writing to `~/.pyxis/logs/trace-<millis>.log`, one file per run. Both files are created before Landlock and granted individually, like `settings.toml`, since the confinement cannot open a path that does not exist yet. The crates only ever emit through the facade: no library writes on a process output any more, and no crate but the binary installs a subscriber. Message and tool-input content only appears at `trace`. Unset variable: no subscriber, no output, an atomic level check per emission point. Delivered by EP-006 of `tasks/prd-harness-capabilities.md`; `crates/agent-cli/src/observability.rs`.
- Terminal causes, everywhere, in one vocabulary: a turn that ends `failed` or `interrupted` carries a bounded cause in its durable log, and ONE classifier (`agent_runtime::TurnFailure`) reads it for every surface, so the TUI, `pyxis -p`, the JSONL summary and the app-server cannot name two different categories for the same fault. Nine closed categories, each with its own next diagnostic step: `provider`, `auth`, `context`, `invalid_request`, `model_runtime`, `guardrail`, `interrupted`, `store`, and `unknown` for a cause the classifier does not recognize (reported as unrecognized rather than guessed into the wrong diagnostic). The transcript, the stderr line, `run_summary.cause_category` and `turn/completed.causeCategory` all carry the same category, the same sentence and the same `thread`/`turn` identifiers, which is what ties a screen to a session file. Nothing about the durable format changed: `cause` is still the string it was, so every session file written before this stays readable and no migration touches a user journal. A Code Mode cell states `running`, `yielded`, `completed` or `failed` as WORDS in the transcript, including when it failed, where the red tint used to be the only carrier. Under `PYXIS_LOG=debug` the correlation comes from nested spans rather than from fields repeated at each emission site: the runtime opens one `turn` span (thread, turn), the registry a `tool` span (tool, call), and a cell an OS thread of its own that the engine re-attaches to its caller's span and collector, so a provider, tool, V8 or child failure traces under `thread -> turn -> call -> cell` with no prompt, tool output or token in it. Remote observability is absent BY CONSTRUCTION, not by a runtime guard: no OTLP exporter is in the dependency graph, enforced against `Cargo.lock`, so an unconfigured or unreachable collector cannot cost a connection or a local diagnostic. Delivered by US-019 of `tasks/prd-parite-totale-codex-cli.md`; `crates/agent-runtime/src/failure.rs`, `crates/agent-cli/src/failure_line.rs`, acceptance in `crates/agent-runtime/tests/observability.rs`.
- Parity as a runnable recipe: `docs/parity/offline-suite.md` names, per contract domain (catalogue, function/custom wire, Code Mode, terminal, multi-agent v2, resume, app-server, MCP, errors), the file and the test that prove it WITHOUT network or an OpenAI account. That document is parsed by `crates/agent-parity/tests/offline_suite.rs`: a renamed test or a domain that loses its proof fails the suite instead of leaving a paragraph claiming coverage it no longer has. `cargo run -p agent-parity -- drift` is the upstream watch: it reads the Codex clone at whatever commit it is on, ignores the commit number itself and reports whether the CONTRACT moved, writing nothing to either repository — moving a baseline stays a decision, never the side effect of a command. The one live scenario (`crates/agent-cli/tests/live_parity_sol.rs`, `PYXIS_LIVE_PARITY=1`) runs a real `gpt-5.6-sol` prompt and writes a tri-state verdict to `target/parity/live-verdict.json`: `skipped` without opt-in or credential, `passed` with a Code Mode cell plus a terminal result plus a resumable transcript, `external_error` with the exact OpenAI error. The verdict file is what must be read, not the green test, so a `skipped` can never pass for proof. Delivered by US-020 of `tasks/prd-parite-totale-codex-cli.md`.
- Docs rename: `pyxis` is the public command and repo name. Internal crates still use `agent-*`.
- Composer: multi-line input (Alt+Enter, Ctrl+J, Shift+Enter where the terminal reports it), wrapped rendering with a 10-line cap and vertical scrolling, and large pastes collapsed to a `[collage : N lignes]` summary that expands to the full content on submit. Delivered by EP-003 of `tasks/prd-harness-parity.md`; `crates/agent-tui/src/composer.rs` holds the wrap and cursor mapping.
- Configuration: TOML parsed by the reference library, resolved by NAMED layers each carrying a declared precedence (`settings::ConfigLayer`): global settings 10 < profile 15 < project config 20 < environment 25 < command line 30. The winner of a key is decided by comparing those numbers, never by the order the layers happen to be applied in, and `/status` names the layer every non-default value comes from. `permission_mode`, `sandbox_mode`, `writable_roots`, `hooks` and `profile` are security keys: the project file is dropped on them with a warning naming the layer, and so is `-c key=value`, because an argument can come from a script of the repository and is therefore no more trustworthy than a workspace file. `--permission-mode` and `--sandbox` do carry them, since choosing a perimeter for one session is what they are for, and a widening of the headless default is announced on stderr with the layer that caused it. A `[profiles.<name>]` table groups model, effort, permission mode and sandbox policy; the scope of the file that DECLARES it decides whether it may carry a security key, so a profile written by the repository widens nothing. An unknown profile refuses to start and lists the declared ones; an unusable key of a profile is dropped alone. An invalid file names its line and key and starts on defaults instead of failing. Delivered by US-016 of `tasks/prd-harness-parity.md`, then EP-002 of `tasks/prd-parite-codex-par-le-code.md`.
- Machine output: `pyxis -p --output-format json` writes one JSON event per line, each carrying a schema version, ending with a `run_summary` line (session id, model turns, cumulative tokens, end cause, exit code). Schema in `docs/EVENT_SCHEMA.md`; the default text output is unchanged. Delivered by US-017.
- Turn diff: every turn exposes an aggregated diff of the files it touched, including files written by a `bash` command rather than by an edit tool, as the structured `AgentEvent::TurnDiff`. Rendered as a one-line summary in the TUI, emitted as `turn_diff` in the JSONL stream. Delivered by US-018; `crates/agent-tools/src/turn_diff.rs`.
- Session surface: 22 slash commands. EP-006 of `tasks/prd-parite-codex-par-le-code.md` adds five. `/init` runs a bootstrap turn that inspects the repository and writes `AGENTS.md`; an instruction file already there (`AGENTS.md` or the tolerated `CLAUDE.md`, symlink included) is never overwritten without the explicit `/init force`, because leaving that guard to the permission pipeline would mean `accept-edits` and `auto` approving the overwrite unasked. The file counts from the NEXT turn on with no restart: the project context is read once, before the turn, so `/init` re-reads it when the turn ends, through the same `project_messages` the startup uses (same block order, hence the same cacheable prefix). `/fork` and `/rewind` ask the runtime for a branch at a terminal turn boundary and switch to it; the source thread keeps exactly the bytes it had (see the thread-runtime entry above). `/copy` puts the last answer in the clipboard as it was streamed, through the first available helper (`wl-copy`, `xclip`, `xsel`, or `pbcopy` on macOS), bounded by 3 seconds since it runs inside the event loop; no helper means a named error, never a silent "copied". `/logout` and `/providers subscription codex disconnect` share one sign-out path and both say that only the LOCAL credential is deleted: nothing revokes the ChatGPT session server-side. `/hooks` lists what is declared with its event and matcher, which is also the answer to "can this repository run something behind my back?" — `hooks` is a global key, so the answer is no.
- Thread runtime: a conversation is owned by a durable local actor (`crates/agent-runtime/`), and BOTH clients drive it through the same `ThreadHandle`. Every thread, turn, step, event and agent carries an opaque identifier; a turn holds one of `queued`, `running`, `needs_input`, `completed`, `interrupted` or `failed` and produces exactly one terminal state, persisted before it is announced. Operations enter a bounded mailbox (64) that refuses rather than blocks, and an accepted operation is durable before its acknowledgement. A message typed while a turn runs is a STEER: it enters the running turn at its next safe point (before a model request, never between a `tool_use` and its result), or opens a turn of its own if that turn ended first — never both, never neither. An interruption is acknowledged in the time it takes to flip a token and reaches the model, the tools and their process trees through one cancellation tree; the terminal state is written after reconciliation, and a task that ignores the signal for 2 s is aborted, drained, and reported. `/fork` branches at the last completed turn, `/rewind <turn-id>` at a named one; both materialize the durable prefix into an independent file carrying `parent_thread_id`, the fork turn and the fork event, and neither truncates, rewrites nor deletes the source. A thread reopened rebuilds its transcript, its last state, its captured configuration and its agent graph; a turn a crash left without a terminal is closed once, after the orphan tool calls are answered. The session file is the thread log: one file, one writer, one cursor, so the transcript and the transitions cannot disagree. No orchestration key exists in `settings.toml`, the profiles or the CLI: every limit (mailbox 64, live stream 256, pending inputs 16, 4 active sub-agents, 8 created, depth 1) is a runtime constant, and `/status` shows them next to the thread and turn in force. Delivered by `tasks/prd-runtime-orchestration-durable.md`; race harness in `crates/agent-runtime/tests/races.rs`, durable E2E in `crates/agent-session/tests/e2e_thread.rs`.
- Headless in a pipeline: `-p` no longer demands its value. Without one the prompt is read from standard input; with one, the argument wins and standard input is not read at all, so a `-p` that already carries its prompt never drains a pipe left open for something else. Nothing on either side is a named error rather than a wait, and a terminal standard input counts as nothing. `--output-last-message <path>` writes only the last assistant message there, raw, whatever the outcome, since the exit code is what tells a script whether the run succeeded; the destination obeys the sandbox policy instead of widening it, on the same reasoning as `-c` (an argument can come from a script of the repository). `--ephemeral` opens no session file at all and does not even create `.pyxis/sessions/`, nor ask for a write right on it: the thread runs on the in-memory store adapter. It is refused with `--resume` and outside `-p`, because `/new`, `/fork`, `/rewind` and `/resume` all open a thread file that would not exist. Ctrl+C now goes through the runtime rather than the default handler: the turn stops cooperatively, reconciles its transcript, writes its own `interrupted` terminal and the run exits non-zero with `end: "interrupted"` on the summary line. Delivered by EP-006 of `tasks/prd-parite-codex-par-le-code.md`.

- Public OpenAI Responses BYOK mode and server-side `previous_response_id` mode.
- Per-server MCP OAuth, the superseded SSE transport, and MCP resources / elicitation / progress notifications. The app-server's server-request correlation is generic, so an elicitation will travel it without a second path when MCP grows one.
- App-server surfaces outside the thread/turn/item cycle: accounts, cloud tasks, `fs/*`, marketplace, realtime and the 123 other baseline methods are PRD non-goals.
- Rich TUI: nested plan trees (the plan renders as a flat list of steps) and hunk-level diff review.
- A mutating sub-agent: measured no-go, recorded in `docs/DECISIONS.md`. Isolation would require widening the sandbox or letting the model write `.git`.
- Vector memory, prompt-cache strategy, VCR provider tests, packaged releases, macOS Seatbelt, and cross-platform hardening.

## Live Risks

- ChatGPT subscription auth is unofficial and revocable. It is a convenience channel, not a contractual foundation.
- Network control is proxy-based and cooperative. It helps for HTTP(S) subprocesses, but it is not a kernel-level network sandbox and does not block raw sockets by itself.
- Linux is the only supported sandbox target today. Off-Linux filesystem confinement degrades explicitly.
- Deferred-execution subpaths (`.git/` as a whole, which covers `hooks/`, `config`, and the worktree `gitdir:` pointer file, plus `.pyxis/`) are refused before any permission decision, including through a symlink, and that protection now covers `bash` as well (US-002 of `tasks/prd-parite-codex-par-le-code.md`). The subtraction is evaluated at POLICY level rather than by the kernel, which is the only level that can take back a right Landlock has granted, since its rules only ever add. The rule is fail-closed on the TARGET, not on the command: a command that is not proven side-effect free is refused as soon as it NAMES a protected path, whether or not the write can be demonstrated. Two consequences are deliberate. A command of the side-effect-free set is exempt, so `cat .git/config` stays a read and stays allowed. And a read performed by a program outside that set (`tar --exclude=.git ...`) is refused; naming no protected path is always an alternative.
- Residual limit of that guard, and the answer to the open question of US-002: a path BUILT at run time (`p=.g; cat ${p}it/config`) is invisible to any static analysis and escapes it. Closing it would take a shell interpreter, which the non-goals of the PRD exclude. The blast radius is unchanged from before: no security key is ever honored from `.pyxis/config.toml` (US-016), so writing that file still buys nothing.
- A command blocked by the confinement is named as such in the result the model reads, so it stops retrying variants of the same command (US-004). Only the NETWORK perimeter can then be widened, for that one call, after an explicit confirmation that no permission mode short-circuits and that is never remembered. The filesystem perimeter cannot: a Landlock domain is inherited by every child and irreversible for the process, so no in-process escalation can lift it and none is offered. Changing it means restarting with another `sandbox_mode`.
- `edit` and `apply_patch` both stay available, and the choice between them is documented in the tool's own behavioral guidelines: `apply_patch` for several sites or several files, `edit` for a single unique anchor. That is the measured answer to the open question of US-010, not a default: on 22 tasks run twice against `gpt-5.3-codex-spark`, `edit` failed 3 calls out of 39 (7.7%) and `apply_patch` 0 out of 24, both finishing 22/22. The failure-rate gap is not significant at that sample size (Fisher p = 0.28); the clear gap is cost, 38% fewer calls for the same work, and every `edit` failure was an anchor that was ambiguous or no longer found on a multi-site edit. Full write-up in `docs/apply-patch-vs-edit-2026-07-27.md`, replayable harness in `docs/bench/edit-vs-apply-patch/`.
- Terminal sessions (`exec_command` / `write_stdin`) carry the baseline wire since EP-004 of `tasks/prd-parite-totale-codex-cli.md`: `cmd`, `workdir`, `shell`, `tty`, `yield_time_ms` and `max_output_tokens` in, `chunk_id`, `wall_time_seconds`, `exit_code`, `session_id`, `original_token_count` and `output` out, rendered as the text the Codex models are trained to read. `tty: true` allocates a REAL pseudo-terminal (`openpty` + `setsid` + `TIOCSCTTY`, no `portable-pty` dependency), which reverses the US-012 answer: a program that checks `isatty` now behaves in a session exactly as it does under Codex. `tty: false` keeps the pipe session. Divergences that are deliberate: `chunk_id` is a monotone per-session counter instead of a random hex string, a pipe session still accepts standard input, and `write_stdin` carries a `terminate` that brings the process group to a terminal state in under two seconds. An absent workdir, a non-POSIX shell and the fifth concurrent session are refused BEFORE the spawn, so a refusal never leaves a process behind, and what is written to a session's standard input goes through the same protected-subpath guard as a command, since a shell session would otherwise be the way around it.
